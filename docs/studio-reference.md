# 本地 SoulX Studio 优化实现参考

本项目后续以本机 `%LOCALAPPDATA%/SoulX Studio` 的实际工作流为主要参考。这里记录已核对的实现语义与本工具对应改进，避免把上游原始推理脚本当作完整产品。

| 本地参考 | 实现要点 | 本工具对应改进 |
| --- | --- | --- |
| backend/models.py 的 Segment.unit_timings | 每个字词有实际起止时间 | 对齐结果持久化；主歌词点击按实际字词定位 |
| backend/service.py 的 correct_original_lyrics | 区分原唱识词校正和改词 | 原词校正接口；保留用户已经修改的新歌词 |
| backend/service.py 的 update_timeline_segment | 保存时间轴、联动相邻唱句并处理过期产物 | 句边界联动、逐字拖动联动、范围/重叠校验、生成指纹失效 |
| backend/models.py 的逐字时间请求结构 | 时间轴是可编辑数据而非显示估算 | 独立时间轴编辑器、逐字试听和时间保存 |
| backend/timeline_analysis.py 与对齐组件 | 先分析再供编辑/生成使用 | 独立对齐任务；不必先合成整句才能获得时间 |

## 当前使用方式

打开顶部“歌词时间轴”，左侧选句：

1. 校正“原唱实际唱词”，保存；已改过的新歌词不会被覆盖。
2. 点击“提取当前句逐字时间”，或在主页点击“提取未对齐歌词”批量处理。已有时间不会被批量覆盖；每次最多处理 100 句，超过后可再次点击。模型任务只做对齐，不加载演唱模型。
3. 点击文字试听，修改每字/词的起点和终点，保存。
4. 回到改词/生成界面。后续生成复用已保存时间，并在日志记录 alignment_cached。

自动识词使用本机 FireRedASR2 生成草稿，界面会持续标记待校对，直到用户在时间轴确认原词。时间轴中可拆分当前句或与下一句合并，拆分要求原词与新词发音单位数量一致；这两项操作会使相关旧对齐和生成结果失效。

主歌词按中文汉字、完整英文单词建立按钮，保留原有空格和标点。可用逐字时间时按真实时间定位并高亮；缺少时间时明确标为估算。

## 数据一致性

对齐缓存取决于原始音频、原词和句子边界，新歌词变化不必重复对齐。原词或句子边界改变后自动失效。手动时间参与生成指纹，旧音频会变为过期。模型任务中途发生新的手动修改时，旧结果不能覆盖手动数据。

手动值以秒保存、输入步长 1ms，每个字词至少 20ms。模型内部按声学帧工作，输入毫秒精度不等于毫秒级声学精度。重新提取时间会使当前句已有音频过期，界面会先确认。

## 验证与边界

已用实际唱句完成“独立提取 13 字时间 → 手动修改 → 保存 → 复用时间生成”的完整验证。单元测试还覆盖原词校正不丢改词、缓存失效、时间重叠、旧任务结果拒绝覆盖。

波形现在按显示宽度每约 2px 绘制一根细线，底层保留约 5ms 的峰值包络；以非静音峰值的第 96 百分位归一化显示幅度，实际音频增益不变。立体声使用各声道最大绝对值，避免左右声道抵消隐藏瞬态。

整句编辑和逐字编辑均支持波形拖动边界、拖动文字块整体平移、缩放、视窗平移、撤销/重做及方向键微调。逐字边界推到相邻字时会联动调整，每个字保留至少 20ms；整句边界推到相邻句时，保存会同步调整相邻句，当前句和受影响的相邻句至少保留 120ms。保存前会提示涉及的相邻句，边界改变后相关对齐和生成变为过期。点击空白定位，逐字列表可试听。编辑后仍需点击保存，保存的时间通过已有生成接口复用。

## 开源社区参考

- [JIZURA](https://github.com/852wa/JIZURA)：实际阅读 `index.html` 的 `bind()` 时间轴事件与拖动处理，参考指针捕获、鼠标锚点缩放、Shift 滚轮平移与编辑历史的交互设计；本项目波形组件独立实现，使用当前服务的绝对秒时间数据。
- [Folia](https://github.com/chthollyphile/folia-major)：已查阅项目与技术介绍，作为歌词播放、逐字显示和后续歌词动效的参考；本次没有引入其代码或声称完成全部歌词动效。
- HubertFA、Vocal2Midi、Qwen3-ASR：对齐与音符提取已在当前生成管线使用，具体版本见模型集成文档。

尚未实现 MIDI 钢琴卷帘和跨发音单位数量的改词适配；这些不能视为已完成。开源致谢列表提供了可核对的参考来源，具体功能仍按运行结果逐项验收。
