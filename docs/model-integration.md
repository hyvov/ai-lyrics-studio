# SoulX-Singer 接入核对

## 来源

2026-11-03 核对 [Soul-AILab/SoulX-Singer 官方仓库](https://github.com/Soul-AILab/SoulX-Singer)。官方说明代码与模型采用 Apache-2.0，并支持 F0 旋律条件与 MIDI 乐谱条件。实际引入时保存依赖版本、许可证及声明文件；本仓库当前未复制其代码或权重。

## 本机静态检查

安装的模型运行时中存在 SoulX-Singer `model.pt`、RMVPE、ROSVOT 与 ForcedAligner 文件。读取了 core 中的 `cli/inference.py` 和 `soulxsinger/utils/data_processor.py` 以核对数据结构，没有导入商业应用后端，也没有触发 GPU 模型加载。

GPU 检查结果为 RTX 5060 Ti、约 16 GB 显存；检查时约 7.4 GB 已占用。该数字仅是当时快照，不能据此保证实际推理可运行。原 SoulX Studio 正在运行。

## 实际输入要求

上游流程需要参考干声音频、参考元数据与目标元数据。元数据至少涉及：

- `time`：片段时间范围，以毫秒为单位。
- `phoneme`：音素/发音序列，包含停顿。
- `duration`：各槽位持续时间。
- `note_pitch`、`note_type`：音符及类型，与槽位对应。
- `f0`：连续音高条件。

因此不能把 LRC 文本或同字数歌词直接当作推理输入。必须先完成原词校对、音高提取、音符/发音对齐和新词音素适配。生成时应裁剪参考音频，统一局部时间零点，验证采样数与片段长度，并将结果放回工程时间轴。

## 下一阶段的最小验证

1. 在独立模型环境中获取上游代码，固定版本并核对依赖；权重使用显式配置路径。
2. 用短干声片段与已校对歌词完成一次预处理，检查槽位和音高。
3. 替换一句歌词，构建独立目标元数据，生成真实 WAV。
4. 检查吐字、音高、时长、首尾接缝及显存峰值；生成失败不标记完成。
5. 通过子进程适配器接到后台任务，串行使用 GPU。输入指纹包含素材、边界、歌词、音高与模型版本，拒绝旧结果覆盖新编辑。

现阶段没有实际运行唱歌推理，也没有声称合成测试音证明了演唱质量。
